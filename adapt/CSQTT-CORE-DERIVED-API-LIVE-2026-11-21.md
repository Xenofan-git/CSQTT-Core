# CSQTT Core — реальный ARM64 API тест, 2026-11-21

## Проверенный бинарник

Адаптированный CSQTT Core 2.5.0, локально сохранённый ARM64 ELF из ранее проверенного релиза 10aa3f1e4344d317bf5c2f638da80e4d065401fc.
SHA-256 бинарника: 771453b7efc155ffc60cbecdf03581a957e6b292c7d5fb63435ec4a482a570ad.
Исходная версия CSQTT: fd936ef087c34cc46f26111dc2361f43b8b03c07.

Важно: это НЕ новый ARM64 выпуск №7 из коммита 21c59ba. Для него отдельного живого CRUD-теста пока нет.

## Изоляция

Московский VPS; ARM64 ELF запущен через QEMU user mode с загрузчиком AArch64.
Внешний UID/GID процесса — 65534 (nobody), root UID доступен только внутри отдельных user и network namespaces.
Внутри отдельной сети доступен только loopback, маршрута по умолчанию нет.
Системные сетевые команды ip, iptables, sysctl, systemctl и systemd-run заменены тестовыми командами в PATH.
Тестовые файлы и база SQLite размещались во временном каталоге, который удалён после тестирования.

Использован уже имеющийся тест реального API adapt/test-csqtt-original-server-e2e.py.
Разрешение на изменение тестовых записей ограничено isolated-only и HTTPS URL с секретным префиксом на 127.0.0.1.

## Результаты

Состоялось два запуска одного и того же реального адаптированного ARM64 бинарника с остановкой и повторным стартом между ними на общей временной базе.
- Первый запуск: HTTPS HTTP 200, 32/32 реальных API проверок PASS.
- Второй запуск после остановки: HTTPS HTTP 200, 32/32 PASS.
- Анонимный доступ к статистике отклонён, авторизованная сессия выдаёт HttpOnly и Secure cookie.
- Настоящие CREATE/READ/UPDATE/DELETE клиента и группы, проверка сохранения правок.
- Экспорт, безопасный импорт с выключенной модификацией, защищённые endpoints logs и settings.
- Удалены только тестовые клиент и группа; сверены оригинальные наборы клиентов и групп, общие настройки не изменились.
- Проверен неизменный маршрут по умолчанию внешнего VPS до и после испытания.
- Остановлены тестовые процессы; временные файловые каталоги и тестовая база удалены.

Итог: 64/64 PASS, два старта и корректная очистка данных.

## Наблюдения / ограничения

В более раннем бинарнике появляется предупреждение startup policy cleanup timed out; на доступность HTTPS/API не влияет. Отдельное исправление предупреждения проверено в более позднем ARM64 CI, но это не тест его API.
При одном из запусков обнаружено служебное сообщение восстановления привязки main_sub_uuid в тестовой SQLite. Тест подтвердил сохранность клиентов, групп и настроек, но не проверял реальные токены.
Проверка настоящих сетевых маршрутов/TUN/DTLS/SOCKS5 не проводилась (сетевые команды подменены, изоляция намеренная).
Не проверена работа API нового релиза №7, реальный systemd Deploy, forced rollback и физический NanoPi.
Это локальное испытание, а не новый GitHub Actions SUCCESS.

Никаких изменений рабочего CSQTT Core, NanoPi, Keenetic, HydraRoute, или глобальной маршрутизации не производилось.
