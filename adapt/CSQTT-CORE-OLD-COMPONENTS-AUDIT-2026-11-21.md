# CSQTT Core — старые компоненты: проверенный состав

**Дата:** 21 ноября 2026. **Основа продукта:** оригинальный CSQTT 2.5.0.
**Режим:** только аудит; не менять рабочий NanoPi, маршрутизацию и Deploy.

## Компоненты и решение

| Компонент | Что реально происходит | Решение |
| --- | --- | --- |
| Интегрированная ARM64 сборка | Из оригинала CSQTT **2.1.9** и согласованного стороннего Rust-клиента собирается адаптированный сервер **CSQTT-WIRE-4** | Считать *legacy-интеграцией*, **не выдавать за релиз 2.5.0** |
| Бинарники APK 2.1.9 | Используются как эталон/источник для проверок, но стандартные csqtt-linux-arm64/amd64/armv7 и старый deploy.sh **исключены из конечного архива** | Дополнительно удалять нечего |
| Сервер csqtt-lalune-linux-arm64 | **Входит** в интегрированный пакет; manifest csqtt.server-provenance.json указывает sourceTag v2.1.9, WIRE-4, SHA-256 | Пока не подменять бинарником 2.5.0 без тестов |
| Go/Linux-контроллер | Нужен для HTTP панели, профилей, запуска клиента, TUN/SOCKS5 и sing-box | Оставить, не переписывать |
| Отдельный Rust-клиент | В старой интеграции собирается из закреплённого отдельного источника вместе с WIRE-4 сервером | Для релиза 2.5.0 тестировать клиент и сервер **вместе** |
| Отдельная Rust ARM64 сборка | Утверждённый исходник CSQTT v2.5.0, SHA fd936ef087c34cc46f26111dc2361f43b8b03c07, отдельный ELF | Оставить, но не считать проверенным с текущим клиентом |
| Штатный Deploy 2.5.0 | Уже существует адаптер от оригинального deploy.sh: adapt/derive-csqtt-core-deploy-250.py | Не переписывать с нуля |
| Gateway / WireGuard | Отдельный эксперимент, не основной семивкладочный runtime | Не интегрировать и не удалять без подтверждения |
| Технические названия lalune-* | Часть systemd/путей/JSON/имён API и CAPTCHA | Механически не менять: риск потери совместимости |
| VK token fetcher и CAPTCHA | Нужны CSQTT Core | Сохранить |

## Почему нельзя просто заменить сервер

Из исходника оригинального CSQTT **2.5.0** подтверждено:
`rust-server/main.rs` объявляет
`WIRE_PROTOCOL_REVISION = "CSQTT-WIRE-3"`.
Старая интегрированная сборка проверяет
`--protocol-revision = CSQTT-WIRE-4`.
Это **разные ревизии**, которые не следует считать взаимозаменяемыми
без реального теста клиента и сервера. Возможность совместимости или
переговоров о версии отдельно пока не доказана.

**Минимальная необходимая работа для полноценного выпуска 2.5.0:**
проверить согласованную пару Rust-клиента и сервера от 2.5.0 с текущим
Go/Linux и sing-box; затем испытать оригинальный адаптированный Deploy
2.5.0 и откат **в отдельной ARM64 VM**. Не менять уже работающие правила,
API и процессы без выявленного дефекта. Ранее пройденные неизменённые
тесты не повторять без причины.

## Что проверено на NanoPi (только чтение)

- `lalune-backend-native.service` включена и работает;
  путь `/usr/local/bin/lalune-backend-native`.
- По проверенным стандартным путям **не найдены** отдельные
  `/usr/local/bin/csqtt`, `/usr/local/bin/csqtt-core`,
  `/usr/local/lib/lalune/server-assets/csqtt-lalune-linux-arm64`,
  `/etc/csqtt-core`, `/etc/csqtt-lalune`.
- HTTP `/version` без авторизации возвращает `401`.
  Версия работающего бинарника этим способом **не установлена**;
  название unit само по себе не доказывает наличие Rust-сервера 2.1.9.
- hydraroute-core и tailscaled активны, default route остаётся
  192.168.4.1 через eth0. Никаких перезапусков и изменений не делали.
